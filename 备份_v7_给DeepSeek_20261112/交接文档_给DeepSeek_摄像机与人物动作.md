### 3.2 Maya 本地文件轮询通道

项目已有可信的本地文件执行器，优先使用它，避免命令端口安全弹窗：

```text
<工作区>\scripts\wb_poller.py
<工作区>\scripts\mcmd.py
<工作区>\cmd\
```

`wb_poller.py` 会监控 `<工作区>\cmd` 中的 `cmd_*.py`，执行后写入结果 JSON，并把命令改名保存。不要删除这些文件和目录。

从外部 Bash 执行现有 Maya 脚本的格式：

```bash
python -c "import sys; sys.path.insert(0, r'C:\Users\admin\Desktop\MayaProject\让子弹飞分镜测试\工作区域文件夹\scripts'); import mcmd; print(mcmd.run_file(r'C:\Users\admin\Desktop\MayaProject\让子弹飞分镜测试\工作区域文件夹\scripts\你的脚本.py', timeout=180, tag='ds_test'))"
```

重要：`mcmd.run_file()` 返回 `{"ok": true}` 只说明文件被 poller 执行，不代表脚本内部业务检查通过。必须继续读取脚本自己写出的日志，检查 `errors`、业务 `ok` 和输出文件。

## 6. 骨骼命名和动画基准

### 6.1 马县长：新 Bip001 骨名

主要关节：

```text
Root
└─ Bip001
   └─ Bip001Pelvis
      ├─ Bip001Spine
      │  └─ Bip001Spine1
      │     └─ Bip001Spine2
      │        └─ Bip001Neck
      │           └─ Bip001Head
      ├─ Bip001LThigh / Bip001LCalf / Bip001LFoot
      ├─ Bip001RThigh / Bip001RCalf / Bip001RFoot
      └─ 左右 Clavicle / UpperArm / Forearm / Hand
```

主要手臂节点：

```text
Bip001LClavicle
Bip001LUpperArm
Bip001LForearm
Bip001LHand
Bip001RClavicle
Bip001RUpperArm
Bip001RForearm
Bip001RHand
```

新模型有手指骨，但用户明确说手指不用动，不要给手指打关键帧。

### 6.2 黄四郎和师爷：旧模型英文前缀

黄四郎使用 `Huang_`，师爷使用 `Shiye_`。主要节点：

```text
Root / Center / Groove / Bone
Spine / Spine1 / Neck / Head
LeftShoulder / LeftArm / LeftArmTwist / LeftForeArm / LeftHandTwist / LeftHand
RightShoulder / RightArm / RightArmTwist / RightForeArm / RightHandTwist / RightHand
LeftUpLeg / LeftLeg / LeftFoot
RightUpLeg / RightLeg / RightFoot
```

手臂链含 `ArmTwist` 和 `HandTwist`，不要把这些扭转骨当成主肘关节。两段 IK 的主中间关节是 `ForeArm`。

### 6.3 当前姿态就是动画基准

- v7 当前没有任何动画曲线。
- 关节当前局部旋转包含中立姿态和两段 IK 结果，不能直接设成 `(0,0,0)`。
- 开始动作前，从 `ds0_scene_snapshot.json` 或实际场景保存当前局部旋转、世界矩阵和位置。
- 新关键帧应在当前基准上做增量，或根据世界目标求姿态，不要套用旧脚本中的固定角度。
- 旧的 `Head.rotateY ±17`、`Spine.rotateX=6` 等写法已证明过于粗糙，不要直接复用。

### 6.4 世界空间旋转的关键经验

本项目实测：Maya 行向量约定下，世界增量四元数应右乘旧朝向：

```python
new_q = old_q * delta
```

不是 `delta * old_q`。

写回时可使用临时世界朝向约束，让 Maya 处理父级旋转和缩放，再删除约束并保留关节旋转。每次写回后必须重新读取子关节世界位置，不能只检查数学目标。

### 6.5 两段 IK 的当前实现

v7 使用解析两段 IK，而不是依赖本场景里表现异常的 `ikRPsolver`：

1. 读取起点、中间关节、末端世界位置。
2. 根据两段骨长、末端目标和极点求中间关节位置。
3. 用世界增量旋转先对齐第一段，再对齐第二段。
4. 将结果写入普通关节旋转，不保留 IK 手柄。
5. 读取末端实际位置复核误差。

完整实现见：

```text
<工作区>\scripts\q3_rebuild_pose.py
```

警告：该脚本当前输出文件名仍写成 `摆姿重建_v7.mb`。如果要复用函数，先复制成 DS 自己的脚本并改输出路径；不要在已经加好相机和动作的 v7 上直接重跑，否则会重建并覆盖基线。

## 8. 摄像机重做规则

### 8.1 原片是依据，旧 shots.json 不是机位依据

旧 `gen_shots.py` 的核心问题：

- 按动作文本里第一个人名决定主体。
- 只按主体、景别和“左/右移动”生成弧形机位。
- 没有真正解析前景人物、视线、镜头承接和起止关系。
- 旧 `v10_prod.mb` 的 71 台相机按位置和朝向去重后只有 12 种，最大一组重复 18 次。

因此旧 `eye0`、`eye1` 只能用于证明旧逻辑，不得直接作为新机位。

### 8.2 每镜必须读取的内容

1. `shot_id`。
2. `start_frame` / `end_frame`。
3. `shot_size`。
4. `action`：谁在说、看谁、谁反应、是否有手部动作。
5. `camera_move`：从哪里开始、往哪里移动、是否承接上一镜。
6. 前景人物及其画面左右位置。
7. 对话者是否在镜头外。
8. 原片首、中、尾和关键动作帧。

### 8.3 180° 轴线

三人围坐不代表可以围绕桌心任意取机位。

- 为每对对话者建立关系轴。
- 在前几个镜头确定正反打所在侧。
- 后续保持同一侧，除非原片明确越轴并且有相应调度。
- 每镜在设计表中记录所用轴线。
- 检查相邻镜头人物视线方向是否匹配，不能只比较相机坐标。

### 8.4 前后景关系

以下镜头不能只拍单人居中：

- S003：师爷头必须在画面右侧前景，并按要求向右进入前景。
- S004：马县长必须在画面左侧前景，原文为“四成多”，需要看原片确定占比和运动含义。
- S018、S019、S021、S022、S036 等包含镜头外人物或前景动作的镜头，也要按原片处理。

建议用相机空间投影检查前景头部/肩部是否真正入镜，不要只把人物名字写进 JSON。

### 8.5 运镜

- 运镜起止关键帧必须分别落在该镜的 `start_frame` 和 `end_frame`。
- 起点值和终点值必须真的不同。
- 运镜幅度要匹配镜头时长；S042 只有 9 帧，不适合大幅绕弧。
- “向右移动”要根据当前相机朝向定义，不要一律只改世界 X。
- “向上”“向下”“跟镜头向上”“轻微晃动”分别处理，不得统一成水平漂移。
- 不要用随机扰动冒充原片运镜。
- 不要给所有镜头套同一个正弦摆动。
- 定镜镜头应保持相机稳定，动作由人物完成。

### 8.6 景别和焦距

不要给所有近景使用同一个距离和焦距。

- 近景、胸上景、面部特写、中景、带前景双人关系应分别根据原片确定。
- 焦距、距离、相机高度和瞄准点共同决定景别。
- 正式相机使用透视投影；观察相机的正交设置不要带入正式分镜。
- 当前场景使用 cm，注意距离数量级。
- 相机近/远裁剪面可先使用 `5 / 2200`，此前过宽范围曾导致深度精度闪面。

### 8.7 相机命名和保存

本项目实测 `cmds.camera(name=...)` 的返回节点可能带后缀。必须保存返回值：

```python
created = cmds.camera(name="DS_S003_CAM")[0]
camera_map["S003"] = created
```

之后全部使用 `camera_map["S003"]`，不要假设名字一定是没有后缀的 `DS_S003_CAM`。

建议新相机放入独立组：

```text
DS_PRODUCTION_CAMERAS
```

不要混入 `POSE_REVIEW_CAMERAS`。

保存相机映射到新文件，例如：

```text
<工作区>\ds_camera_action\camera_map_deepseek.json
```

不要覆盖旧 `logs\cam_map.json`。

### 8.8 视口切换与缓存

- 先查询当前可见 `modelPanel`，本次通常为 `modelPanel4`，但每次都要实际查询。
- 使用真实存在的相机名执行 `lookThru(panel, actual_camera)`。
- 仅执行 `modelEditor(..., camera=...)` 曾在本项目中静默留下旧相机，不能单独依赖。
- `lookThru` 后应查询面板当前相机，并渲染首帧核对。
- 不能只检查 PNG 是否生成；要核对不同机位图片哈希和实际画面。
- playblast 使用 `clearCache=True`、`viewer=False`、`showOrnaments=False`。
- 预热帧只用于清缓存，不得混入正式序列。

## 9. 人物动作范围和制作方法

### 9.1 允许的动作

- 头部转向对话者。
- 轻微点头、仰头、低头。
- 视线节奏和停顿。
- 手部抬起、指向、接近桌面、拿放道具的简化动作。
- 必要时肩部随手臂自然联动，但不能破坏 v7 躯干和坐姿。

### 9.2 禁止或默认不做的动作

- 不做嘴型。
- 不做手指动画。
- 不做 root 整体左右摇摆来冒充表演。
- 不重复旧脚本中“每镜固定转 ±17°”的模板。
- 不通过 `Spine` 固定角度叠加制造大幅前倾。
- 不给旧 MMD 模型安排大角度弯臂。
- 不因为分镜写有站起、前倾，就自动扩大用户“只做头部和手部”的许可范围。

### 9.3 分镜身体动作与当前范围的冲突

S014、S016、S022、S028、S032、S036–S038、S045、S056、S069、S070 等含有前倾、站起、坐下或身体调度描述。

当前默认处理方式：

- 保持 v7 坐姿和身体稳定。
- 用头部、手部、视线和相机运动表达节奏。
- 不实际站起，不重新动画腿部。

如果用户要求这些镜头严格复刻身体站起/坐下，必须先单独确认扩大动画范围，再做腿部和身体动画。DeepSeek 不应自行决定。

### 9.4 头部动作

- 以当前头部世界旋转为基准。
- 先确定“看谁”：马县长、黄四郎、师爷、桌面、道具或镜头外位置。
- 可为视线目标建立临时 locator，但要记录并清理/管理约束。
- 每个动作键应对应分镜节奏，不要所有镜头都用首中尾同一模板。
- 视线换目标要有短暂停留，不要匀速来回摆动。
- 头部转向后检查脖子、肩部和桌面构图，防止过度扭转。

### 9.5 手部动作

马县长：

- 使用新 Bip001 手臂链。
- 大角度弯臂可以用新模型，但仍要检查袖口、肩、肘、腕。
- 手肘极点放在身体外侧、通常低于桌面；根据实际穿桌情况调整。
- 手腕目标不等于手掌接触面，必须看网格。
- 指向动作不需要手指弯曲，可保持手型不变。

黄四郎、师爷：

- 保留自然腿侧/腿上手部位置。
- 只做小幅度动作。
- 如果袖口或网格破裂，优先简化手部动作，不要破坏躯干，也不要用 Delta Mush 掩盖。

### 9.6 酒杯和道具动作

当前没有道具绑定，只有 1 杯、1 瓶、1 碗。

如果制作拿杯、碰杯、倒酒：

1. 先确认镜头里是否真的需要完整动作，还是可以用前景/切镜简化。
2. 检查杯子数量和位置。
3. 如需三只杯子，复制现有杯子，记录新增节点。
4. 使用保持世界变换的约束或其他明确绑定方式。
5. 检查手指不需要动，但手掌和杯子不能分离或穿插。
6. 检查杯子底部与桌面接触。
7. 倒酒时还要检查瓶口、杯口和另一只手的位置。
8. 先出关键帧静帧，再做短段。

不要为了赶进度把杯子长期穿在手里，也不要在没有绑定的情况下只移动手腕而杯子完全不动，却宣称完成拿杯动作。

### 9.7 残留 blendShape

场景仍有旧黄四郎和师爷的 2 个 blendShape 节点。当前没有动画曲线，本阶段未用它们做新表演。

- 不做嘴型。
- 不需要为“有动作”而启用所有形态键。
- 如果使用眨眼，必须单独确认对应权重和视觉效果；否则保持原状态。
- 新马县长没有导入那批完整表情 morph，不要重新导入。

## 11. 静帧、短段和全片验收标准

### 11.1 静帧验收

每张正式静帧至少检查：

- 主体是否完整可见。
- 景别是否与原片接近。
- 头部是否朝向正确对象。
- 前景人物是否在正确一侧。
- 桌面、椅子、手和道具是否穿插。
- 袖口是否完整。
- 相机是否穿墙、穿桌、穿人。
- 近远裁剪是否造成闪面。
- 是否误带原片顶部表格。
- 图像是否与其他机位重复。

### 11.2 短段验收

- 镜头切换发生在正确帧。
- 相邻镜头视线匹配。
- 没有无意越轴。
- 运镜起止有真实变化。
- 动作在切镜处没有不自然跳变。
- 手部与道具没有突然分离。
- 没有全段静止、全段同机位或全段统一摆动。
- 音频若启用，台词与对应镜头同步。

### 11.3 全片渲染前的硬性检查

- 71 个镜号全部存在。
- 帧范围总和精确为 3512。
- 每镜相机真实存在且被实际使用。
- 每镜帧数等于 `end-start+1`。
- 原始序列总数必须等于 3512；如果多出，必须查明原因，不能用 `files[:3512]` 截断掩盖。

### 11.4 不要重复旧报告的假通过

旧评审曾出现“8/8 PASS”，但漏掉静止图、错误姿态、穿模和闪面。DeepSeek 的报告必须区分：

- 节点存在。
- 节点参数正确。
- 节点在渲染中实际生效。
- 最终画面经过目视确认。

## 12. 渲染、字幕、音频和编码

### 12.1 渲染目录必须新建

不要覆盖旧 `frames_raw3`、`frames_all3`、`frames_sub`。建议：

```text
<工作区>\ds_frames_raw
<工作区>\ds_frames_all
<工作区>\ds_frames_sub
<工作区>\ds_qa
```

每次正式渲染使用新目录或明确的新版本目录，避免旧帧混入。

### 12.2 playblast 帧范围

旧 `f8_render_all.py` 可参考 `startTime` / `endTime` 的逐镜输出方式，但不能直接运行，因为它会打开旧 `v11_handfix.mb` 并读取旧相机映射。

注意旧坑：

```python
frame=[f0, f1]
```

这只表示两个帧的列表，不是连续区间。可以：

- 使用正确的 `startTime` / `endTime`；或
- 显式传 `frame=list(range(f0, f1+1))`。

每镜渲染后立刻检查数量，不要等 71 镜结束才发现只渲了首尾两帧。

### 12.3 预览与最终分辨率

- 静帧和短段默认可用 854×480，与旧预览一致。
- 原片为 1920×1080。
- 是否在最终阶段升 1080P，需要用户确认；本机约 8GB 内存，不应自行决定高质量全片渲染。

### 12.4 帧率

新场景动画前改为 23.976fps。最终图像序列编码必须：

```bash
-framerate 24000/1001 -start_number 1
```

不要直接运行旧 `g3_encode.sh`，它写死了 `-framerate 24`。

### 12.5 字幕

- 当前已有 51 张字幕 PNG，位于 `<工作区>\subs`，尺寸基于 854×480。
- 字幕在后期烧入，不在 Maya 里做嘴型或字幕平面。
- 如果最终仍为 480P，可评估复用，但必须核对帧范围、台词和画面可读性。
- 如果改 1080P，应重新生成，不要直接放大低分辨率字幕。
- 虚拟环境已有 Pillow 12.3.0。
- 字体可用 `C:\Windows\Fonts\msyh.ttc`。
- 旧评审指出白字压在白色道具上可读性差；必要时使用半透明底板和 2px 描边。
- 字幕必须在画面和剪辑确认后最后烧入。

### 12.6 音轨

原片有 AAC，旧 v2 没有音轨。

最终是否把原片音轨按同一时间轴回贴，需要用户确认。若启用：

- 使用原片音轨，不生成新的配音。
- 检查起始偏移。
- 检查镜头台词与音轨对应。
- 核对成片视频和音频时长。
- 不要只检查 `nb_frames`，还要检查音频流是否存在。

### 12.7 编码后验证

最终至少用 ffprobe 核对：

- 宽、高。
- `r_frame_rate` 是否为 `24000/1001`。
- 帧数是否 3512。
- 容器时长。
- 是否有音频流。
- 文件大小是否合理。

再抽取首帧、末帧、每个镜头切点和关键动作帧检查。不要只凭编码命令退出码为 0 就宣布完成。
